Built on VS Code

Your setup comes with you.

{{name}} is a fork of VS Code (Code - OSS). The editor you know is all there, and {{name}} adds to it.

  1. Your extensions

    From Open VSX, the open registry VS Code forks use.

  2. Your themes, keybindings and settings

    The same commands, shortcuts and settings.json.

  3. Import from VS Code

    One click on first launch, or Insilode: Import from VS Code…. Settings, keybindings, snippets and theme come from VS Code or Cursor; extensions on Open VSX are installed, the rest are listed.

    Reading pane

    Read it like a debugger that runs nothing.

    The code opens beside the canvas. Step into a call, over it and back out; the canvas keeps the trace: the path to your cursor solid, what you have read plain.

    • l step into
    • j step over
    • h step out
    • Enter open a peek
    • [] back, forward

    Change review

    Your agent changed 2 files. Which endpoints did it reach?

    One canvas holds the whole change: every endpoint it reaches, added lines in green, removed in red. Keep or undo each change where you see it.

    1. 2 files changed
    2. 4 endpoints reached
    3. 1 table changed
    • Against your uncommitted work, the branch, the last commit, or where the agent's session began.
    • Test files and whitespace-only edits are left out, and so are comment-only edits in most languages.

    Agents

    Three agents are running. Which one needs you?

    Claude Code, Codex and any CLI run as their real tools, in terminals. The Agents dock ranks what needs you first; the status island at the top of this page is the one the app can put at the top of your screen.

    Codex waits to run the billing tests.

    • A window of its own

      Keep the Agents page open on its own, with insilode --agents-only; the editor is one click away.

    • Worktrees

      Start an agent in its own git worktree and merge it back with one click. You are warned when two agents edit the same file, method or flow.

    • Context, cost and limits

      Each row shows the model, how full its context window is, tokens and cost; the status bar shows what is left of your 5-hour and weekly limits.

    • Pull requests and CI

      The state of each agent's branch, its pull request and its checks, on its row.

    • Every window

      Sessions of your other {{name}} windows, grouped by project, and the ones other programs run, read-only.

    • The next one that needs you

      On the Agents page every session that waits for you sits in a strip above the panes; AltShiftN jumps to the next.

    Harness

    Your agent reads a dozen files before you type. Is any of them wrong?

    CLAUDE.md, AGENTS.md, rules, skills, hooks, MCP servers and permissions on one map, with a health score. Broken rules and hooks that never fire are found without an LLM.

    • Why? The instructions, rules and permissions that apply to a file.
    • Simulate a permission. Would Bash(git push --force) be allowed, asked or denied, and by which rule?
    • Friction inbox. Permissions you keep granting and corrections you keep repeating become proposed rules.
    • MCP servers. See, check, add and edit the servers of Claude Code and Codex.

    On the canvas

    Boards, tours and diagrams, from your code.

    • Boards

      Agents draw flow, plan, class, ER, sequence, architecture and state boards on the canvas, or sketch freely.

    • DTO and architecture diagrams

      Drawn from your types. Copy a diagram as Mermaid, or export a board as Markdown.

    • Tours

      Ask how something works and the agent plays a tour of the flow, step by step, with pen marks.

    • Point and ask

      The ? on a card asks your agent about exactly that card.

    • Migrations

      An edited migration lists the endpoints that touch each table it alters.

    • Updates

      A running {{name}} checks for the next release; on Windows it installs it in place.
